# 机器人消息管理模块（botMessage）

用来让**整个管理组**都能维护「由机器人发出的常驻消息」（社区规则、公告、置顶说明等），
不必再有人单独拿 bot token 去第三方客户端里改。

---

## 一、指令一览

模块只占用 **1 个斜杠指令 + 1 个右键指令**（服务器斜杠指令上限是 100 个，需要省着用）。

### `/机器人消息`

| 子指令 | 作用 |
| --- | --- |
| `编辑` | 修改机器人已发出消息的文字（正文 / 嵌入卡片） |
| `发送` | 用机器人在指定频道**或论坛帖/子区**发一条新消息 |
| `发帖` | 用机器人在论坛频道开新帖，**首楼归机器人**，之后可随时编辑 |
| `替换` | 用一条「草稿消息」的内容整体覆盖目标消息（适合长文、复杂排版） |
| `撤销` | 把消息回退到上一次改动之前的版本 |
| `历史` | 查看某条消息的改动记录（谁、什么时候、改了什么） |
| `配置` | 配置可用身份组、操作日志频道 |

### 右键菜单：`编辑机器人消息`

在消息上 **右键 → 应用 → 编辑机器人消息**，是日常最快的入口：

- 纯文本消息 / 只有一张卡片的消息 → 直接弹出编辑窗口
- 多张卡片、或带按钮的消息 → 先弹出一个选择面板，选要改哪一部分

---

## 二、消息怎么定位

凡是需要填「消息」的地方，以下三种写法都支持：

1. **消息链接**（推荐）：右键消息 → 复制消息链接
2. `频道ID-消息ID`：开启开发者模式后右键消息 → 复制消息ID 得到的格式
3. **纯消息ID**：会在当前频道里查找

---

## 三、几条硬性限制（Discord 侧，不是本模块的限制）

- **只能编辑本机器人自己发出的消息。** 别的机器人、Webhook、用户发的消息，Discord 一律不允许本机器人改。
- **消息正文最多 2000 字**；嵌入卡片描述最多 4096 字，但**弹窗输入框最多 4000 字**——
  超过 4000 字的卡片描述无法在弹窗里编辑，请改用 `替换` 子指令。
- **不能给已发出的消息追加/替换附件。** `替换` 只复制文字和嵌入卡片，来源消息的附件不会被搬过去。
- **子区被锁定时无法编辑**（除非机器人有「管理子区」权限）。归档则不用管，见下。

## 三点五、消息在已归档的帖子里怎么办

**不用手动解归档，机器人会自己处理**：检测到目标消息所在子区/论坛帖处于归档状态时，
会先临时解除归档 → 完成编辑 → 立刻恢复归档，操作回执里会说明这一步发生过。

需要注意的是，Discord 会拒绝一切发往已归档子区的交互响应（连仅自己可见的回复也不行，
报错 `50083 Thread is archived`），所以**解归档必须发生在机器人回应你之前**。
模块已经按这个顺序处理：先解归档 → 再响应交互 → 编辑 → 恢复归档。

只有一种情况仍会失败：**子区已归档且被锁定，而机器人没有「管理子区」权限**。
这时 Discord 不接受任何响应，弹窗只会显示它自带的那句「出现错误，请重试。」
（该文案由 Discord 客户端写死，机器人无法自定义），控制台会打出具体原因。
解决办法是给机器人「管理子区」权限，或手动解除归档后再改。

## 三点五四、往论坛帖 / 子区里发消息

**Discord 的频道选择器列不出论坛帖和子区**，只能选普通频道。所以 `发送` 提供了两个入口：

| 选项 | 用途 |
| --- | --- |
| `频道` | 普通文字频道 / 公告频道，从下拉里选 |
| `帖子或频道` | **论坛帖、子区**，填链接或ID |

`帖子或频道` 接受这几种写法：

- 帖子/子区链接（右键帖子 → 复制链接），带不带消息ID都行
- `<#频道ID>` 形式的频道提及
- 纯ID（开发者模式下右键 → 复制ID）

**两个都不填时，默认发到你执行指令的当前位置**——人在哪个帖子里就发到哪个帖子，最省事。

目标帖若已归档，机器人会自动解除归档再发言。注意这里和「编辑」的处理**不一样**：
编辑完会把归档状态还原，而发送**不会归档回去**——正常成员往归档帖发言时 Discord 本来
就会让帖子保持活跃；若立刻归档，刚发的消息反而会被折叠起来看不见。回执里会说明这一点。

## 三点五五、在论坛里发常驻帖

**为什么需要这个**：论坛帖的首楼是发帖人本人的消息。人工发帖的话首楼归你，
机器人无权编辑，`编辑` 功能就用不上了。想让常驻规则帖可以被整个管理组维护，
必须**一开始就由机器人来建帖**。

```
/机器人消息 发帖 论坛:<论坛频道> 标题:<帖子标题> [标签:<标签>] [形式:...] [来源消息:...] [允许提及:...]
```

- **标题**：最长 100 字（Discord 限制），必填
- **标签**：支持自动补全，可多选（用逗号分隔，如 `公告, 规则`）。
  也可以直接填标签名或标签ID。**论坛若开了「必须选标签」，不填会被拦下并列出可用标签**
- **形式**：
  - `纯文本（弹窗输入）` —— 默认，弹窗写首楼正文
  - `嵌入卡片（弹窗输入）` —— 首楼是一张卡片
  - `复制另一条消息的内容` —— 配合 `来源消息`，把写好的草稿整篇搬成首楼（推荐用于长规则）

发完之后回执里会给出首楼跳转链接。之后要改，直接右键首楼 → 应用 →
`编辑机器人消息`，或者用 `/机器人消息 编辑` 填首楼链接。

几个限制：

- 机器人需要在该论坛有「创建公开帖子」和「在帖子中发言」权限，缺哪个都会明确提示
- 一个帖子最多 5 个标签（Discord 限制）
- 弹窗形式下，帖子标题和标签会先暂存在服务端 20 分钟；
  弹窗开着放太久再提交会提示会话过期，重新执行指令即可
- 附件同样不会被复制

## 三点六、想 @ 到人要注意什么

发新消息时有个 `允许提及` 选项，默认**否**（只渲染成高亮文字，不推送通知）。
设成 `是` 之后仍然 ping 不到人，通常是下面三种情况之一：

**1. 弹窗输入框没有 @ 自动补全（最常见）**

在 Discord 正常输入框里打 `@张三` 会弹出候选列表、选中后变成一个真正的提及。
但**模态窗口里没有这个功能**，你打的 `@张三` 就只是四个普通字符，永远不会 ping。

要在弹窗里写提及，得用 Discord 的原始格式：

| 目标 | 写法 |
| --- | --- |
| 用户 | `<@用户ID>` |
| 身份组 | `<@&身份组ID>` |
| 频道 | `<#频道ID>` |
| 全体 | 直接写 `@everyone` / `@here` |

> 更省事的办法：用 `发送 形式:复制另一条消息的内容`。
> 先在普通输入框里把消息写好（@ 自动补全正常可用），再把那条草稿的链接填进来，
> 机器人复制的是原始内容，提及格式天然就是对的。

**2. 内容放在嵌入卡片里**

嵌入卡片内的提及**永远只渲染不推送**，这是 Discord 的规则，跟本模块无关。
要 ping 人就得写在消息正文里。选了卡片形式又开了 `允许提及` 时，回执会提醒你。

**3. 机器人没有「提及所有人」权限**

正文里写了 `@everyone` / `@here`，但机器人在目标频道没有该权限时不会真正推送，
回执同样会提醒。

另外注意：**编辑已发出的消息时一律不触发提及**，没有开关。
这是有意为之——改个错别字不应该把 `@everyone` 重新推送一遍。

## 四、长文 / 复杂排版怎么改

推荐工作流：

1. 管理员在任意频道（比如一个管理组内部频道）把新版规则写成一条**草稿消息**，反复润色；
2. 执行 `/机器人消息 替换 目标消息:<常驻规则消息链接> 来源消息:<草稿消息链接>`；
3. 机器人把草稿的文字与卡片原样搬到目标消息上。

同理，`/机器人消息 发送 形式:复制另一条消息的内容` 可以把草稿直接发成一条新的常驻消息。

## 五、安全设计

- **权限**：服务器所有者 / Discord 管理员 / `core/utils/permissionManager.js` 里配置的管理身份组
  始终可用；其他身份组需要通过 `/机器人消息 配置 操作:添加可用身份组` 加入白名单。
- **可见性**：两个指令都是 `setDefaultMemberPermissions(0)`，即**默认对所有非管理员隐藏**
  （与 `/处罚`、`/风纪` 一致），不依赖「管理消息」之类覆盖面过大的原生权限。
  要让某个身份组能用，需要**两步**：
  1. 服主到 **服务器设置 → 整合 → 本机器人 → 权限** 里为该身份组显式放行这两个指令；
  2. 用 `/机器人消息 配置 操作:添加可用身份组` 把它加入模块白名单（代码级校验）。

  两道关卡是「与」的关系，少任何一步都用不了。
- **跨服务器保护**：只能操作当前服务器的消息。
- **越权保护**：操作者必须自己能看到目标频道，否则拒绝。
- **提及保护**：编辑已发出的消息时一律不触发提及（`allowed_mentions: {parse: []}`），
  改个错别字不会把 `@everyone` 重新推送一遍。发新消息时默认同样不推送，需要真 @ 到人时把
  `允许提及` 设为 `是`。
- **链接预览不受影响**：正文含链接时 Discord 自动生成的预览卡片会被识别并跳过，
  既不会被误当成可编辑卡片，也不会在编辑时被固化成真正的嵌入卡片。
- **面板消息提醒**：目标消息若带按钮 / 选择菜单（多半是投票、自助身份组、赛事等系统的面板），
  会在编辑前提示——改文字不会破坏按钮，但对应系统刷新面板时可能覆盖你的改动。

## 六、留痕与回滚

- 每次改动都会把**改动前后的完整快照**写入 `data/botMessage.sqlite`，每条消息保留最近 30 个版本。
- `/机器人消息 撤销` 回退最近一次改动；再执行一次相当于「重做」。
- `/机器人消息 配置 操作:设置操作日志频道` 之后，每次编辑 / 发送都会在该频道留一条记录
  （操作人、目标消息跳转、变更前后摘要）；改动前内容较长时会附带完整 `.txt` 备份。

## 七、文件结构

```
src/modules/botMessage/
├── index.js                          # 模块启动 + 按钮/弹窗交互路由
├── commands/
│   ├── botMessage.js                 # /机器人消息（编辑/发送/替换/撤销/历史/配置）
│   └── editBotMessageContext.js      # 右键菜单「编辑机器人消息」
├── components/
│   └── messageModals.js              # 各类模态窗口构建 + 颜色解析 + customId 常量
├── services/
│   ├── botMessageService.js          # 核心逻辑：编辑/发送/替换/撤销/日志
│   └── botMessageDatabase.js         # SQLite：配置 + 改动历史
└── utils/
    ├── botMessagePermissions.js      # 权限判定
    └── messageResolver.js            # 消息链接解析、拉取、快照、rich embed 过滤
```

接入点：

- `src/core/index.js`：注册两个指令 + `startBotMessageSystem()`
- `src/core/events/interactionCreate.js`：按 `botmsg_` 前缀转发按钮与弹窗交互
